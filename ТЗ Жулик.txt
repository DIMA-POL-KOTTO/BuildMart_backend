ТЗ: подключить авторизацию к интерфейсу BuildMart
Цель
Добавить вход и регистрацию на одной странице, а также отображать состояние пользователя в шапке сайта.
1. Страница входа и регистрации
Создать frontend/auth.html. На странице должны быть обе формы: вход и регистрация. Между ними пользователь переключается без перехода на другую страницу.
Поля входа: email и пароль. Поля регистрации: email, пароль и подтверждение пароля. Показывать понятные сообщения об ошибках от API и не очищать введённые данные при ошибке.
Использовать существующие маршруты:
- POST /api/auth/register с JSON { "email": "...", "password": "..." }. Успешный ответ — 201; пароль должен содержать не менее 8 символов.
- POST /api/auth/login с тем же форматом. Успешный ответ содержит token и user.
- GET /api/auth/me с заголовком Authorization: Bearer <token> — получить пользователя при восстановлении состояния входа.
Регистрация сама токен не возвращает, поэтому после успешной регистрации показать форму входа или выполнить вход отдельным запросом.
2. Шапка сайта
Для гостя отображать ссылку или кнопку «Войти», ведущую на auth.html.
Для вошедшего пользователя отображать кнопку с его идентификатором и пункт «Выйти». При обновлении страницы проверять сохранённый токен через /api/auth/me. Если сервер отвечает 401 — очистить токен и показать шапку гостя.
Сейчас модель пользователя содержит email, но не имя. Поэтому отображать email; если требуется отдельное имя, это нужно согласовать как дополнительное изменение модели и API.
Шапка повторяется на нескольких HTML-страницах. Логику её состояния нужно вынести в общий скрипт, например frontend/js/auth/auth_ui.js, и подключить на всех страницах с шапкой.
3. Работа с токеном
После успешного входа сохранять JWT и передавать его в запросах к защищённым API через Authorization: Bearer <token>. Для текущего многостраничного фронтенда подойдёт sessionStorage. Пароль не сохранять.
Выход должен удалить токен и сразу обновить шапку. Отдельного API-маршрута выхода сейчас нет.
Критерии готовности
- Вход и регистрация доступны на одной странице.
- Ошибки валидации и ответы API отображаются пользователю.
- После входа пользователь видит свой email в шапке на всех страницах.
- После обновления страницы состояние входа восстанавливается через /api/auth/me.
- После выхода пользователь видит гостевую шапку.
- Просроченный или недействительный токен сбрасывает состояние входа.
Работу ограничить фронтендом: существующие auth-маршруты и API не менять.
